

## TwiYo demo notes (these replace the starter assumptions above)

This website is a frontend-only React/Vite prototype for a sample shop and marketing-services concept. It has no application server/database, payment integration, customer or lead storage, email/CRM routing, or product analytics. Cart state and fake order details exist only in React memory and disappear when the page reloads. Checkout accepts fictional contact/fulfilment fields only; it has no payment fields and no network submission. The enquiry confirmation is local UI feedback and says explicitly that the enquiry was not sent or saved. Platform analytics injection is disabled; hosting, preview and content delivery infrastructure may still process technical requests.

### Preview and local development

The managed Preview uses port 3000. Start its static Vite development server with `pnpm dev:static` (the managed environment supplies `PORT`). For local development, run `pnpm install`, then `pnpm dev:static`. To verify the demo, run `pnpm quality:demo`, `pnpm check`, `pnpm test`, and `pnpm build:static`; output is in `dist/public` and includes route-specific crawlable pages generated by `scripts/prerender.ts`. The dependency-light demo guardrail is documented in [`docs/DEMO_QUALITY_GATE.md`](docs/DEMO_QUALITY_GATE.md). The GitHub Actions workflow repeats these checks on pushes and pull requests.

### Updating the site

- **Products, illustrative prices, labels and images:** edit the exported `products` array in `client/src/data/siteData.ts`. Keep prices labeled as examples until the currency and real catalogue are approved. Replace each sample image URL with an approved asset when available.
- **Services and sample scope:** edit the `services` array in the same file. Update descriptions, sample deliverables, exclusions, process, pricing and timeline only after business approval. Avoid unsupported outcome promises.
- **Page headlines and browser metadata:** edit `pageMeta` and `routeLinks` in `client/src/data/siteData.ts`; route-specific metadata feeds the static prerenderer. Then run `pnpm build:static` so output pages are regenerated.
- **Policy copy:** edit `policyContent` in `client/src/pages/Info.tsx`. Current language is a placeholder, not legal advice or a launch-ready policy.
- **Page layout and interactions:** edit the relevant file under `client/src/pages/` and shared components under `client/src/components/`. Cart state/quantities and the fake confirmation reference live in `client/src/contexts/CartContext.tsx`.
- **Colors, typography and responsive layout:** edit CSS variables and media queries in `client/src/index.css`. Electric lime is the signature accent; warm paper and ink anchor the minimal editorial layout.
- **Custom artwork:** image URLs are in `siteData.ts` or the homepage JSX in `client/src/pages/Home.tsx`. The current hero, product and service images are draft-generated visuals served from Manus storage. Replace these with TwiYo-approved assets before a real store launch. If an async image ever fails, the layout keeps its bespoke CSS fallback artwork and hides the broken-image glyph while retaining accessible alt text.
- **Page routes:** update `client/src/App.tsx`, `client/public/manus-routes.json`, and the route data handled by `scripts/prerender.ts` together.

### Decisions before launch

Confirm the operator/legal identity; target country and markets; launch language and currency; real products/prices/images; stock and fulfilment; payment provider and settlement; approved services/prices/terms; real support channels; shipping/returns; privacy/terms/cookie consent; analytics/CRM/email integrations; secure admin roles and MFA; audit/access controls; data retention/export/deletion; backup/monitoring; and deployment ownership. The admin screen is a fictional mockup without authentication or data management. Do not enable real transactions or enter real customer details in this demo.
